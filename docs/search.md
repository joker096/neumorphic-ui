# Поиск и адресация сообщений

## 2. Глобальный поиск

`GlobalSearch` держит запрос и три фильтра в локальном состоянии — `dateFilter`, `senderFilter`,
`typeFilter` (`all` по умолчанию), а также историю запросов (`loadHistory()` → `localStorage`) и
`activeIndex` для клавиатурной навигации по результатам. Рендер секций вынесен в
`search/SearchResults.tsx`, чтобы компонент не разрастался: результаты группируются по типу
(чаты / сообщения / контакты) и каждая строка — отдельная кнопка с 44px хит-зоной.

Поиск открывается из левого рейла и по `Ctrl/Cmd+K`; после выбора результата вызывается
`openChat`, который поднимает нужный чат в `App` и может передать `__jumpToMessageId` для скролла
к конкретному пузырю (тот же механизм, что у ссылок на сообщение, см. §4).

## 3. Поиск внутри чата

`useChatPreviewSearch({ chat, savedMessages, scheduledMessages, lang, t })` — единственный владелец
состояния поиска в открытом чате. Возвращает:

- `searchQuery` / `setSearchQuery` — сырой ввод; фильтрация идёт по `useDebounce(searchQuery, 200)`,
  чтобы не пересобирать историю на каждое нажатие;
- `filteredHistory` — сообщения, прошедшие текстовый фильтр и диапазон дат (`dayBounds` для границ
  дня: `new Date("YYYY-MM-DD")` даёт UTC-полночь, поэтому сравнение идёт по локальным границам);
- `mediaItems` — вложения (изображения/видео/файлы) для медиа-табов профиля и панели медиа;
- группы сообщений с локализованными разделителями дней (`groupMessages`, `formatDateLabel`);
- `jumpToDate(date)` — находит первый пузырь указанного дня и скроллит к нему
  `msgListRef.scrollToIndex`; возвращает `false`, если в чате нет настолько новых сообщений
  (честный отказ вместо тихого «ничего не произошло»).

Совпадения подсвечиваются в `FormattedText` (stateless-регэксп, без `g`-флага, чтобы `.test()`
не переносил `lastIndex` между вызовами).

## 4. Ссылки на сообщение

`messageLink.ts`:

- `buildMessageLink(chatId, messageId, origin?)` → `#nexus://chat/<chat>/<msg>`; компоненты
  кодируются `encodeURIComponent`, строка-идентификатор переживает `/` и пробел;
- `parseMessageLink(hash, search)` понимает и фрагмент `#nexus://chat/<chat>/<msg>`, и
  query-форму `?msg=<chat>:<msg>`; чужая схема или неполный путь → `null`;
- `clearMessageLink()` вычищает обработанную ссылку из адресной строки.

`useMessageLinkBoot({ openChat })` (смонтирован в `App.tsx`) одноразово читает ссылку, ищет чат
сначала в `chats`, затем в `channels`, снимает ссылку из URL и открывает чат с
`__jumpToMessageId`. Своего кода скролла у хука нет — прокрутку выполняет существующий эффект в
`useChatPreviewInteractions`. Неизвестный id (ссылка с другого устройства) поглощается молча.

Скопировать ссылку можно из меню сообщения: строка `chat.copyLink` кладёт её в буфер и показывает
тост `chat.linkCopied`.

## 5. Входной гейт P2P-кадров

`authorizeInboundChatFrame(peerId, chatId, chatName, kind)` — единственная точка авторизации
входящего кадра перед мутацией стора или UI. Порядок разрешения чата (`resolveInboundChat`):

1. **`bound`** — чат уже привязан к этому пиру (`chatForPeer`, first-write-wins, пишется только
   после проверки имени). Для этой ветки проверка «имя совпадает» пропускается: транспорт уже
   подтвердил пира, имя могло измениться (контакт переименован);
2. **`id`** — локальный id чата из кадра;
3. **`name`** — bootstrap по имени, единственный кросс-девайсный ключ протокола сегодня.

Для веток `id` и `name` действует правило «нет смешения id и имён»: если имя передано, оно должно
совпадать с именем найденного чата (нормализация — `normName`). Кадр, не прошедший гейт,
отбрасывается **до** изменения состояния, поэтому мёртвые кнопки, пузыри-призраки и устаревшие
реакции не появляются.

Повторы отсекаются `processedMessageIds` (`inboundTransferState.ts`, лимит
`PROCESSED_ID_LIMIT = 1000` на страницу): один и тот же wire-`messageId` обрабатывается ровно один
раз, включая дубли от strict-mode и от нескольких транспортов.

## 6. Известные ограничения (честно, без «verified»)

- **Глобальный поиск** работает по локальному состоянию стора и истории чатов; серверного индекса
  нет, поэтому непрогруженные сообщения не находятся.
- **Первый кадр диалога** разрешается по display name (§5, ветка `name`) — полное закрытие
  требует общего conversation id из публичных ключей обеих сторон.
- **Привязка чат ↔ пир** живёт в памяти: после перезагрузки страницы пир снова разрешается по id
  или имени до следующего входящего кадра.
- **Групповой поиск** по участникам не реализован: группы отбрасываются на входе в P2P-путь,
  поиск идёт только по локальной истории.
- **Медиа-фильтр** ограничен типами `image`/`video`/`file`; фильтра по размеру или отправителю в
  медиа-ленте нет.
