# Полный аудит — 2026-08-17

Сквозной аудит (безопасность, оптимизация, унификация) для Mess&Anger.
Итог цикла: findings ниже + список ключевых функций для дальнейшей разработки.

---

## P0 — Безопасность (критичные)

### S1. `serveAdminFile` крашит REST-сервер на запрос к директории
`server/signaling-server.ts:234-298`
- `GET /admin` или `GET /admin/` → `fileRelPath` = `''`/`'/'` → `join(ADMIN_DIST, '')` = директория → `existsSync()` = true → `readFileSync(<dir>)` бросает EISDIR → **unhandled exception → падает весь REST-сервер (port 8766)**. Это DoS одним запросом.
- Фикс: проверка `statSync().isFile()`, fallback на `index.html`, try/catch. ✅ (исполняется в этом проходе)

### S2. Service worker перехватывает чужие fetch и кэширует API
`public/sw.js`
- fetch-handler не проверяет same-origin → может перехватывать запросы других origin, совпадающие по pattern (`/api/*`, кэшируемые пути).
- Кэширует `GET /api/*` → потенциальный leak JWT-сессий в cache storage.
- Использует deprecated `clients.openWindow` (закрыт в Chrome 111+, fallback ломает navigation).
- `PUSH_VAPID_KEY = ''` → push молча не работает (не баг, но мёртвая настройка).
- Фикс: same-origin guard, exclusion `/api/`, убрать openWindow. ✅ (исполняется в этом проходе)

### S3. Мёртвая и некорректная криптография в `src/lib/crypto/cryptoCore.ts`
- `deriveHKDF()` — назван HKDF, но это **PBKDF2 с 1 итерацией** (OWASP M05: weak crypto). Не используется.
- `performHandshake()` — raw X25519 DH-вывод передаётся как sharedSecret без KDF.
- `encryptMessage()`/`decryptMessage()` — raw DH-вывод напрямую как ключ AES-GCM (без domain separation).
- `generateIdentityKeys()`, `rotateKeys()`, `createForwardSecrecyKey/delete/getForwardSecrecyKey`, `generateHMAC/verifyHMAC/importHMACKey` — не вызываются нигде (проверено по репозиторию).
- `KyberKEM` (ML-KEM768) — мёртв, но это production-зависимость `@noble/post-quantum` и заявленная PQ-архитектура: **решение — подключить к handshake (PQ upgrade) или удалить вместе с зависимостью**. Сейчас оставлен как roadmap-поверхность, помечен в репорте.
- Фикс: удалить мёртвые/небезопасные методы + типы `HandshakeResult`/`EncryptResult`. ✅ (исполняется в этом проходе)

### S4. Трacked binarии SQLite WAL в git
`server/data/admin.db-wal`, `server/data/admin.db-shm` — git-tracked (admin.db закрыт `*.db`, а `-wal`/`-shm` не закрыты). DB-артёфакты в истории = риск утечки данных админки.
- Фикс: `git rm --cached` + `.gitignore`. ✅ (исполняется в этом проходе)

### S5. WS-токен в URL query
`server/signaling-server.ts:83-90` — JWT передаётся в `?token=`. Попадает в access-логи/прокси.
- Риск: средний (нужен сам токен, origin-проверки нет). Полностью корректный фикс = header/cookie + origin check, требует клиентских изменений → **ключевая функция на будущее** (см. K1).
- Минимальное улучшение: origin validation на upgrade (дополнительный слой). ⏳ (backlog)

### S6. `P2PTransport` — HMAC-ключ в открытом виде через signaling
`src/lib/p2p/P2PTransport.ts:134,155,366,379` — `hmacKey` генерируется локально и отправляется в `offer`/`answer` signaling-сообщениях. Зловорокий signaling-сервер/Man-in-the-middle получает ключ аутентификации сообщений.
- Ключевая функция: выводить HMAC-ключ из authenticated DH (publicKey уже регистрируется на signaling → ECDH-кандидат) вместо plaintext-пересылки. ⏳ (backlog, K1)

## P1 — Унификация и мёртвый код

### U1. Тройное дублирование локалей
- `src/locales/*` — 1207 ключей (app)
- `public/lang/*` — 415 ключей (landing)
- `landing/lang/*` — 415 ключей — **байт-в-байт копия** `public/lang/*` (все 8 локалей, MD5)
- Корневая директория `landing/` — полная мёртвая копия `public/landing/` (проверено hash по всем общим файлам; ни один script/CI не ссылается на `landing/`).
- Фикс: удалить корневую `landing/`. ✅ (исполняется в этом проходе)

### U2. Мёртвые хуки
- `src/hooks/useConnection.ts` — хардкод `wss://mess.cvr.name/ws` (обходит `src/config/signalling.ts`), используется только своим тестом.
- `src/hooks/useConnectionSetup.ts` — используется только своим тестом (App.tsx использует `useAppConnection`).
- `src/App.test.tsx` содержит 2 мёртвых `vi.mock` + дублирующиеся моки `useAppLock`/`useAppConnection`/`useChatInteraction`/`useAppView`.
- Фикс: удалить хуки, тесты, моки, строки в `src/hooks/index.ts`. ✅ (исполняется в этом проходе)

### U3. Шим-модуль
`src/lib/cryptoCore.ts` — 14-строчный re-export "для обратной совместимости". Все импортеры уже используют каноничные пути; можно свести к одному месту, но breaking-change risk → оставить, пометить.

### U4. Две копии `crypto` barrel
`src/lib/crypto/index.ts` и `src/lib/index.ts` (barrel) дублируют экспорт. Нормально для lib, оставить.

### U5. `public/` тяжёлый
- `public/app-release-signed.apk` (1.7MB) — артефакт Android-сборки в web public (нужен для download-линка на лендинге; deploy-all.ps1 дублирует его из корня → два источника истины, риск рассинхрона).
- `public/icons/favicon.png` = **1.4MB** — favicon такого размера; нужен resize до ~64KB.
- ICQ assets: 222 файла (101 light + 101 dark skin + звуки), крупнейшие GIF 144KB.
- Итого `public/` = 10.8MB в git.
- Фикс (частичный): favicon resize. ⏳ (backlog, K4)

## P2 — CI/CD

### C1. `security.yml` сломан
- `eslint --no-config --no-eslintrc --plugin security` — флаги `--no-config`/`--no-eslintrc` не существуют в ESLint 10 → шаг падает/пустой.
- CodeQL шаг использует несуществующий action `github/codeql-action-typescript@v1` и `commands: codeql-db-run` → шаг не работает (и при этом `continue-on-error: true` → тихо зелёный).
- Фикс: корректный code scanning workflow (setup + analyze) или удалить шаг. ✅ (исполняется в этом проходе)

### C2. `ci.yml` без lint
`ci.yml` = vitest + tsc + playwright. `npm run lint` (eslint) не гонится в CI.
- Фикс: добавить lint-шаг. ✅ (исполняется в этом проходе)

### C3. npm audit
9 vuln (7 moderate, 2 high) — все в dev-цепочке `@bubblewrap/core` (Android build tool: googleapis→uuid, jimp, tar, file-type). Runtime-зависимости чистые. Низкий приоритет (dev-only), но CI проверяет `--audit-level=high` → 2 high в dev-зависимостях не падают CI (npm audit без `--prod` включает dev). ⏳ (backlog)

## Проверено и OK (не повторять)
- Нет `console.log`/`debugger` в `src/` (esbuild drop в проде)
- Нет `eval`/`new Function`/`child_process`/`dangerouslySetInnerHTML`
- bcrypt cost 12, JWT 24h из env + `sessions` invalidation, TOTP SHA256/6/30s
- SQL — parameterized queries (better-sqlite3)
- CSP: nonce-модель (без `unsafe-inline`), HSTS preload, X-Frame-Options DENY, Referrer-Policy, Permissions-Policy
- Rate limiting: WS connections (10/min/IP), ads endpoints (50/min/IP)
- Admin API: `requireAuth` на все mutating + read endpoints; client endpoints rate-limited
- Path traversal в `serveAdminFile` закрыт (decode + normalize + `..` block)
